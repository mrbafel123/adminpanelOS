# Стартер сайта клиента — правила для разработчика и ИИ-агента

Это основа уникального сайта клиента. Дизайн и вёрстка у каждого сайта свои, а связь с ядром ячейки (админкой) — общая и уже готова. Решения — в ADR-005 (`instructions/adr/`).

## Как устроено

- Контент приходит из ядра ячейки через `@renote/site-sdk` (`src/cms.ts`). Сайт не обращается к базе и не зависит от Payload.
- Типы контента — `@renote/site-sdk/content`. Они генерируются из модели ядра: `pnpm generate:types` в контейнере ядра.
- Один код, два режима (`SITE_MODE`):
  - `ssr` — Node-процесс. Все опубликованные страницы собираются заранее. После публикации в админке ядро присылает сигнал на `/api/revalidate`, сайт обновляет нужные страницы за секунды;
  - `static` — папка `out/` для хостинга без Node. Обновление — новой сборкой.

| Файл | Что делает |
|---|---|
| `src/app/[[...slug]]/page.tsx` | Любая страница из админки: мета-теги, хлебные крошки, блоки, редиректы |
| `src/components/Blocks.tsx` | Отрисовка секций страницы по типу блока |
| `src/components/FormBlock.tsx` | Форма модуля «Формы» с согласием на обработку ПДн |
| `src/app/legal/[slug]/page.tsx` | Документы модуля «Документы и согласия» |
| `src/app/sitemap.xml`, `src/app/robots.txt` | Из ядра, с учётом модуля SEO |
| `src/app/api/revalidate/route.ssr.ts` | Приём сигнала ядра (только `ssr`) |

## Правила

1. **Данные — только через `cms` из `src/cms.ts`.** Не ходить в API ядра `fetch`-ем напрямую: SDK ставит теги кеша, тайм-ауты и обрабатывает отказ ядра.
2. **Новый блок в ядре — новая ветка в `switch` в `Blocks.tsx`.** Ветку `default` с `never` не убирать: она превращает забытый блок в ошибку сборки.
3. **Мета-теги не собирать вручную.** Они приходят готовыми в `data.meta` (модуль SEO); страница только переводит их в `Metadata` Next.
4. **Сайт должен переживать падение ядра.** Не добавлять запросы к ядру, без которых страница не отрисуется; второстепенные данные (меню, контакты) оборачивать в `try/catch`, как в `layout.tsx`.
5. **Ничего серверного вне `*.ssr.ts`.** Статическая сборка не поддерживает `POST`-маршруты и `cookies()`; серверное — только в файлах с суффиксом `.ssr.ts`, они подключаются лишь в режиме `ssr`.
6. **Формы с персональными данными — только через `FormBlock` или `cms.giveConsent`.** Согласие фиксируется до отправки заявки (152-ФЗ).
7. **Картинки — через `cms.mediaUrl()`**: файлы отдаёт ядро.

## Запуск

```bash
docker compose -f deploy/dev/compose.yml --profile site up -d site     # ssr на http://localhost:3220
```

Статика — см. комментарий к сервису `site` в `deploy/dev/compose.yml`.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `SITE_MODE` | `ssr` или `static` |
| `CMS_URL` | Адрес ядра для сервера сайта |
| `NEXT_PUBLIC_CMS_URL` | Адрес ядра для браузера: формы, картинки |
| `SITE_REVALIDATE_SECRET` | Общий секрет с ядром для сигнала об изменениях |
| `NEXT_PUBLIC_CONTACT_PHONE` | Телефон на странице «Сайт обновляется» |
