# Как написать модуль ячейки

Модуль — это подключаемый функционал ячейки: свои коллекции, настройки, блоки страниц, публичные маршруты, фильтры и подписки на события. Решения — в ADR-003, ADR-012 и ADR-013. Образец — `modules/forms`.

## Устройство

```
modules/<id>/
  module.yaml            манифест
  settings.schema.json   настройки модуля (необязательно), форма в админке строится из схемы
  package.json           @renote/module-<id>, зависит только от @renote/module-sdk
  src/index.ts           defineModule({ setup })
  src/protected/         ценная логика: в сборке передачи — байт-код V8 (ADR-009)
  tests/
```

После добавления модуля:

1. Добавить его в зависимости `core/package.json`: `"@renote/module-<id>": "workspace:*"`.
2. Создать миграцию ядра: `pnpm migrate:create <имя>` в контейнере ядра. Схема модулей — часть цепочки миграций ядра (ADR-013).

Каталог модулей собирается при каждом запуске и сборке ядра (`pnpm catalog`): манифесты проверяются, при ошибке сборка останавливается.

## Манифест

```yaml
id: forms                      # совпадает с папкой, kebab-case
name: Формы                    # название в админке
version: 1.0.0
core: '>=0.1 <1.0'             # совместимые версии ядра
requires: []                   # модули, которые должны быть установлены раньше
runtime: inprocess
settings: settings.schema.json
admin:
  menu: { title: Формы }       # группа в меню админки
events:
  emits: [forms.submitted.v1]  # события — только с версией .vN
  consumes: [forms.submitted.v1]
license: { model: subscription, sku: forms-pro }   # или { model: free }
degradation: Заявки принимаются всегда, уведомления копятся в очереди
```

`degradation` обязателен: это текст для владельца ячейки и Платформы о том, что происходит при сбое модуля.

## Что даёт `setup`

| Вклад | Что делает ядро |
|---|---|
| `collections` | Slug `<id>-<name>` (или `<id>`, если имя совпадает), таблица `mod_<id>_<name>`. Скрыты и закрыты, пока модуль не установлен; при истёкшей лицензии — только чтение |
| `blocks` | Добавляются в секции страниц, slug `<id>-<name>` |
| `endpoints` | Маршруты в `/api/m/<id>/…`, в транзакции. Пока модуль недоступен — ответ 503 |
| `filters` | Синхронные точки расширения с бюджетом 50 мс. Превышение или ошибка — вклад пропускается, модуль `degraded` |
| `on` | Подписки на события. Каждая доставка — отдельная задача очереди с повторами; исчерпанные повторы — DLQ |
| `onInstall` / `onUninstall` | Шаги установки и удаления, должны быть идемпотентны |

Внутри обработчиков модуль работает через `ModuleRuntime`:

- `rt.data('<name>')` — только свои коллекции; `{ asSystem: true }` — действие от имени модуля, иначе — с правами пользователя запроса;
- `rt.settings()` — свои настройки;
- `rt.publish(event, data)` — событие уходит в очередь в той же транзакции, что и данные;
- `rt.log(message)`.

## Правила

- Импортировать можно только `@renote/module-sdk`. Импорт `payload`, ядра или другого модуля — ошибка линтера (`@renote/eslint-config/module`).
- В `protected/` — только функции: в сборке передачи они загружаются из байт-кода лениво.
- Тесты деградации обязательны: что происходит, если упали зависимости модуля.

## Жизненный цикл (ADR-013)

`в каталоге → установить → работает ⇄ деградировал → удалить (данные сохранены) → установить снова`

Устанавливает и удаляет модули владелец ячейки: раздел «Модули» в админке или `POST /api/renote/modules/<id>/install | uninstall`.
