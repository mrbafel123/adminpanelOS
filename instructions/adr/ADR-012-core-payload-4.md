# ADR-012. Ядро ячейки на Payload 4

- **Статус:** предложено 2026-10-29, ждёт утверждения владельцем
- **Дата:** 2026-10-29
- **Связанные:** ADR-002, ADR-003, ADR-006, ADR-009, ADR-010 (дополняет, не заменяет)

## Контекст

ADR-010 выбрал Payload кандидатом в основу ядра и задал недельную проверку с порогом 75%. Проверка прошла 2026-10-29: **82 из 90 баллов**, блокирующие критерии не провалены. Подробности — в [отчёте](../spike-payload-report.md).

## Решение

1. **Ядро ячейки строится на Payload 4** (`4.0.0-beta` до выхода релиза), PostgreSQL, Next.js.
2. **Версия Payload фиксируется точно.** Обновление — отдельной задачей через тесты совместимости модулей (ADR-003). При выходе 4.0 переходим на релиз.
3. **Модули видят только `@renote/module-sdk`.** Адаптер ядра превращает модуль в плагин Payload (`definePlugin`). Прямые импорты `payload` и внутренностей ядра в модулях запрещены правилом ESLint.
4. **Пространство модуля:** коллекции `<id>-<name>`, таблицы `mod_<id>_<name>`, публичные маршруты `/api/m/<id>/`, события `<домен>.<событие>.vN`.
5. **События модулей** ставятся задачей в очередь Payload через тот же запрос, то есть в одной транзакции с данными (transactional outbox без отдельной таблицы). Каждый подписчик получает событие отдельной задачей со своими повторами; исчерпанные повторы — DLQ.
6. **В ячейке есть отдельный процесс worker** для очереди задач: очередь Payload в веб-процессе стартует только с первым REST-запросом.
7. **Схема базы в ячейке меняется только миграциями.** `push` разрешён только в dev.
8. **Лимит памяти задаётся в compose каждого процесса ячейки.** Ядро — 512 МБ: с лимитом пик под нагрузкой 183 МБ, без лимита — 568 МБ.
9. **Сайт клиента не зависит от Payload:** типы контента генерируются ядром, сайт ходит в API через `@renote/site-sdk`. Режимы SSR с ISR и статика собираются из одного кода (ADR-005).
10. **Сборка для передачи** (ADR-009):
    - логика `protected/` компилируется в байт-код V8 тем же Node, что работает в образе, и содержит водяной знак;
    - образ на `distroless` без shell;
    - манифесты модулей компилируются в сборку;
    - обязательный шаг CI проверяет, что в образе передачи нет исходников, source maps и строк из `protected/`.

## Рассмотренные альтернативы

| Вариант | Почему отклонён |
|---|---|
| Payload 3.x | API плагинов меняется в 4.0, адаптер модулей пришлось бы переписывать до первого пилота |
| Strapi (запасной кандидат ADR-010) | Payload прошёл порог, проверка Strapi не понадобилась |
| Своё ядро | +2–3 месяца к этапу 2 без выигрыша по критериям |

## Последствия

- Этап 2 начинается с чистого каркаса. Код ветки `spike/payload` — образец, в продукт не сливается.
- В пакетах продукта появляются:
  - `@renote/module-sdk` — типы, `defineModule`, runtime модуля;
  - адаптер модулей в ядре;
  - `@renote/site-sdk` — клиент сайта;
  - стартер сайта;
  - `build:exit`.
- Риск беты: API `definePlugin` помечен экспериментальным. Изменения Payload затрагивают только адаптер ядра, не модули.
- Остаются непроверенными:
  - перенос WordPress (критерий 4);
  - работа на реальном сервере в РФ;
  - обновление ядра под работающими модулями.
