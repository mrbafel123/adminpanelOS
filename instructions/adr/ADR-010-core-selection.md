# ADR-010. Выбор основы ядра ячейки

- **Статус:** утверждено 2026-10-29 (направление и критерии). **Окончательный выбор ядра — после недельной проверки** (план ниже)
- **Дата:** 2026-10-29
- **Связанные:** ADR-002, ADR-003, ADR-009, ADR-011

## Контекст

Ядру ячейки нужны:

- модель контента в коде с автоматической админкой (аналог ACF), потому что все сайты уникальные;
- авторизация и права;
- медиа;
- черновики, версии и откат;
- локализация;
- хуки;
- API для сайта;
- русский интерфейс админки.

Команда — один разработчик и ИИ. Свой CMS-движок с нуля — это многие месяцы до первой пользы, а всё перечисленное уже решено в open-source.

Стек агентства и renoteOS: TypeScript, Next.js, NestJS, Postgres.

## Кандидаты

| Кандидат | Суть | Сильные стороны | Риски |
|---|---|---|---|
| **Payload CMS** | Headless CMS на TypeScript, работает внутри Next.js, Postgres | Модель контента в коде, автоматическая админка, система плагинов, официальные плагины SEO, форм, редиректов, поиска. Лицензия MIT | Зависимость от чужого ядра: между версиями 2 и 3 было крупное изменение API. Нужно проверить текущее состояние проекта |
| **Своё ядро** (NestJS + своя админка) | Пишем всё сами, часть логики из старого кода | Полный контроль | Месяцы работы до уровня Payload. Вся поддержка на нас |
| **Directus** | Headless CMS поверх существующей БД, админка на Vue | Зрелая админка | Лицензия BSL ограничивает коммерческое использование и передачу. Чужой стек UI (Vue) |
| **Strapi** | Headless CMS на Node.js | Популярен | Модель контента хуже подходит для «схемы в коде». Слабее интеграция с Next.js, история болезненных мажорных обновлений |

**Предварительный выбор: Payload.** Directus отклоняется из-за лицензии (критично для ADR-009). Strapi — запасной вариант. Своё ядро — если Payload не пройдёт проверку.

## Критерии и веса

| # | Критерий | Вес | Как проверяем |
|---|---|---|---|
| 1 | Модель контента в коде для уникальных сайтов | 5 | Описать модель типового корпоративного сайта: услуги, кейсы, команда, отзывы, вакансии, страницы с гибкими секциями |
| 2 | Модульный контракт ложится на систему плагинов | 5 | Реализовать модуль `forms` по манифесту ADR-003 как плагин. Проверить safe mode и бюджет хуков |
| 3 | Сборка для передачи и защита кода | 5 | Собрать `build:exit`: обфускация и bytenode для логики модуля. Ядро работает, админка открывается |
| 4 | Миграция с WordPress | 4 | Перенести один реальный WordPress-сайт агентства: контент, медиа, Yoast, ACF |
| 5 | Ресурсы | 4 | RAM процесса core в простое и под нагрузкой. Бюджет ячейки ≤ 700 МБ (ADR-002) |
| 6 | Кастомизация админки | 3 | Русский язык, брендинг агентства, свой раздел «Доступы», модальное окно блокировки модуля (ADR-008) |
| 7 | Лицензия и здоровье проекта | 3 | Лицензия, частота релизов, открытые критические issues, политика мажорных версий **на дату проверки** |
| 8 | Опыт разработки сайта | 3 | Сгенерировать типизированный SDK, собрать стартер в режимах SSR и static export (ADR-005) |
| 9 | Разработка с ИИ | 2 | Насколько быстро ИИ-агент добавляет новый тип контента и модуль по документации |

Каждый критерий оценивается по шкале 0–3. Итог — взвешенная сумма.

## Правило принятия решения

- **Критерии 1, 2 и 3 — блокирующие.** Оценка 0 хотя бы по одному из них исключает кандидата.
- Payload принимается, если набирает **не меньше 75%** от максимума и не имеет блокирующих провалов.
- Иначе — проверка Strapi на тех же задачах (ещё 3–4 дня) или решение о своём ядре.

## План проверки (5 рабочих дней)

| День | Задача |
|---|---|
| 1 | Каркас: Payload + Postgres в Docker, русский язык, модель контента корпоративного сайта (критерии 1, 7) |
| 2 | Модуль `forms` по манифесту как плагин: safe mode, бюджет хуков, лицензия в режиме «только для чтения» (критерии 2, 6) |
| 3 | Импорт одного WordPress-сайта: страницы, записи, медиа, Yoast, ACF (критерий 4) |
| 4 | Стартер сайта: SDK, SSR и static export. Замер RAM (критерии 5, 8) |
| 5 | `build:exit` с обфускацией и bytenode, запуск в чистом окружении. Оценка, отчёт, обновление этого ADR (критерии 3, 9) |

Код проверки — одноразовый. Он не становится основой продукта без отдельного ревью.

## Последствия

- Если выбран Payload:
  - модульный контракт (ADR-003) реализуется как слой над системой плагинов Payload;
  - API Payload не используется в модулях напрямую, только через наш SDK. Это изолирует модули от мажорных изменений Payload;
  - данные модулей разделяются префиксом таблиц;
  - версия Payload фиксируется, обновление — только через тесты совместимости.
- Если выбрано своё ядро: срок этапа «Ядро ячейки» в дорожной карте увеличивается ориентировочно на 2–3 месяца.
