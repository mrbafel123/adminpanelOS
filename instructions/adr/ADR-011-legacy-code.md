# ADR-011. Что берём из старого AdminpanelOS

- **Статус:** утверждено 2026-10-29
- **Дата:** 2026-10-29
- **Связанные:** ADR-001, ADR-003, ADR-006, ADR-010

## Контекст

Старый AdminpanelOS — это прототип: около 20 тысяч строк, из них 4–5 тысяч строк рабочей CMS-логики.

Проблемы прототипа:

- нет модульной системы, все модули жёстко подключены в `app.module.ts`;
- падение любого модуля роняет API, а вместе с ним сайт;
- 24 из 25 общих пакетов пустые, тестов нет;
- деплой через PM2 со сборкой на сервере;
- проект не под git, секреты лежат в файлах.

**Продолжать его нельзя: новая система строится с правильной архитектурой.** Но в нём есть знания и изолированная логика, которые экономят время.

## Решение

| Что | Где сейчас | Решение | Куда |
|---|---|---|---|
| Модель данных SEO, редиректов, robots, sitemap, хлебных крошек, legal, навигации, ревизий | `prisma/client/schema.prisma` | **Справочник** при проектировании модели контента и модулей | Модули ядра ячейки |
| Логика SEO, sitemap, robots, редиректов, хлебных крошек | `apps/client-api/src/modules/{seo,sitemap,robots,redirects,breadcrumbs}` | **Переносим логику** (не каркас NestJS) | Модули `seo`, `redirects` |
| Логика legal-документов | `apps/client-api/src/modules/legal` | **Переносим логику** | Модуль `legal` |
| Логика публикации, ревизий, превью | `apps/client-api/src/modules/publish` | **Справочник.** В Payload это встроено, при своём ядре — переносим | Зависит от ADR-010 |
| Машина состояний обновления | `apps/update-builder/src/lifecycle.ts`, `executor.ts`, `manifest.schema.ts` | **Берём почти как есть** | Agent (ADR-006) |
| Подход реестра блоков на Zod | `packages/block-registry` | **Берём идею** | Схемы настроек модулей, гибкие секции страниц |
| DTO heartbeat, здоровья и инцидентов | `apps/studio-api/src/modules/ingestion/dto` | **Справочник** для контрактов | `@renote/platform-contracts`, `fleet-gateway` |
| Логика fleet, incidents, releases, rollouts | `apps/studio-api/src/modules/*` | **Справочник** | Модуль `platform` в renoteOS |
| UI карточки инстанса, инцидентов, раскаток | `apps/studio-admin/src/app/*` | **Идеи UX** | Раздел «Платформа» в renoteOS |
| Архитектурные документы: безопасность, бэкапы, observability, эволюция модулей, контракты | `instructions/*-v1.md`, `docs/*` | **Берём после ревизии** под новые ADR | `instructions/` нового репозитория |
| nginx-конфиги | `deploy/nginx/*` | **Справочник** (заголовки, кэш) | Конфигурация Caddy |
| Каркас NestJS: auth, RBAC, пользователи, медиа, CRUD страниц | `apps/client-api` | **Не берём** | Даёт ядро (ADR-010) |
| Интерфейс client-admin | `apps/client-admin` | **Не берём** | Админка ядра |
| client-site | `apps/client-site` | **Не берём** | Стартер сайта (ADR-005) |
| installer | `apps/installer` | **Не берём** (каркас) | CLI `renote` (ADR-006) |
| Пустые пакеты, PM2-скрипты, `dist/`, `.next/`, логи, сгенерированный Prisma-клиент | разное | **Удаляем** | — |
| `.env`, `deploy/.env.production`, `instructions/credentials.md` | корень, `deploy/`, `instructions/` | **Не переносим.** Секреты считаем скомпрометированными и перевыпускаем | — |
| `.agents/rules/rules.md` | `../.agents/` | **Не переносим.** Правила относятся к другому проекту (WordPress-плагин resto-crm) | Новый `CLAUDE.md` в репозитории |

## Последствия

- Экономия: **2–3 недели** анализа и спецификаций плюс готовые куски логики для модулей `seo`, `redirects`, `legal` и agent.
- Старая папка остаётся как архив только для чтения до завершения этапа «Ядро ячейки». Затем её можно удалить.
- Перенос логики делается с тестами: у старого кода тестов нет, и тесты пишутся при переносе.
